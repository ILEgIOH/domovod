# Домовод

Мини-приложение для связи жителей многоквартирных домов и управляющих
компаний (УК). Полностью на Python — [Reflex](https://reflex.dev)
компилирует один и тот же код в backend (Python) и frontend (React/TS),
отдельного JS-приложения в проекте нет.

Сделано под хакатон MAX: сценарий входа — по коду/QR-приглашению или прямой
ссылке, без пароля (как в мини-приложениях MAX, где личность приходит от
платформы). УК заводит дом и подъезд тоже без пароля — под капотом создаётся
служебная учётная запись.

## Возможности

**Житель** (входит по коду/ссылке/QR от УК, имя+квартира):
- главный экран дома: объявления, сборы, инициативы, опросы, долги;
- голосует «Я за!» в инициативах, отвечает в опросах (один или несколько
  вариантов, с изменением голоса до закрытия — настраивает автор опроса);
- вносит настоящий (тестовый) платёж за сбор через ЮKassa;
- **предлагает** свой сбор/инициативу/опрос — уходит на модерацию УК
  (мастер из нескольких шагов, статус потом виден в «Мои предложения»:
  на проверке / отклонено с причиной / опубликовано);
- контакты дома: службы (сантехник и т.п.), полезные адреса, поиск
  соседей по имени/квартире, короткая карточка соседа (имя, квартира);
- профиль: смена имени, смена квартиры (тоже через проверку УК),
  переключение между несколькими домами, выход из дома. Пункт
  «Приватность» пока не реализован — в приложении нет переписки между
  соседями, поэтому настраивать доступ к ней ещё не над чем;
- если УК назначила соседа **соадминистратором** — тот же житель получает
  вкладку «Управление» с правами УК в своём доме.

**УК / администратор дома**:
- те же два таба «Дом»/«Контакты», что у жителя, плюс третий —
  «Управление»;
- модерация предложений жителей (принять / отклонить с причиной) —
  отдельная очередь, не смешана с опубликованной лентой;
- прямая публикация объявлений, сборов, инициатив, опросов (без
  модерации для себя же);
- заявки на вступление в дом (подтвердить/отклонить новую квартиру);
- справочник дома: службы, полезные адреса, список жильцов, права
  доступа (назначить/снять соадминистратора, удалить жильца);
- настройки дома: адрес, приглашение (код/QR/ссылка, с перегенерацией),
  удаление дома (с подтверждением фразой).

**Мультитенантность**: каждый дом (`Tenant`) видит только свои данные —
изоляция на уровне запросов к БД по `tenant_id`/`entrance_id`.

## Технологии

- [Reflex](https://reflex.dev) 0.9.x — весь стек на Python, компилируется
  в React-фронтенд + Python-бэкенд (FastAPI/Granian) одним `reflex run`.
- SQLite через SQLModel/SQLAlchemy — для демо; переключается на Postgres
  через `DATABASE_URL` без изменений в коде.
- [ЮKassa](https://yookassa.ru) — приём платежей за сборы. По умолчанию
  публичные тестовые реквизиты (sandbox, работает «из коробки», деньги не
  списываются). Тестовая карта: `5555 5555 5555 4444`, срок `12/30`,
  CVC `000`.
- [segno](https://pypi.org/project/segno/) — генерация QR-кода приглашения.

### Модель данных (`models.py`)

`Tenant` (дом/УК-аккаунт) → `Building` → `Entrance` (подъезд, у него
`invite_code`) → `Resident` (житель подъезда, есть `is_admin` — соадмин).
Контент подъезда: `News` (объявления), `Collection`/`CollectionPayment`
(сборы и платежи), `Debt` (начисления), `Initiative`/`InitiativeVote`,
`Poll`/`PollOption`/`PollVote`, `UsefulAddress` (категория `service` —
служба дома, `address` — полезный адрес, одна таблица на оба раздела
справочника), `PersonalContact` (личные контакты УК/жителя).

У `Collection`/`Initiative`/`Poll` общий паттерн модерации:
`status` = `proposed` → `published`/`rejected`, `proposed_by_resident_id`,
`rejection_reason`. УК-прямая публикация сразу создаёт запись со
`status="published"`, минуя очередь.

### Роли и доступ

`AuthState.role` — `"uk"` или `"resident"`. Житель дополнительно может
иметь `resident_is_admin = True` (назначается УК) — тогда
`has_admin_access` даёт доступ к вкладке «Управление» наравне с УК.
Большинство загрузчиков в `on_load` страницы `/app` рассчитаны на это:
`UKAdminState.load_admin_data` и подобные сами проверяют
`has_admin_access` и ничего не делают для обычного жителя.

## Локальный запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
reflex run --env prod --single-port
```

Приложение откроется на http://localhost:3000. Для разработки с горячей
перезагрузкой — `reflex run` (без `--env prod`).

## Переменные окружения

См. [.env.example](.env.example). Все переменные необязательны — без них
приложение работает с тестовыми реквизитами ЮKassa и локальной SQLite.

## Деплой на Render (бесплатно)

1. Запушьте репозиторий на GitHub.
2. На [render.com](https://render.com) → New → Blueprint → укажите
   репозиторий — Render подхватит `render.yaml`.
   (Либо вручную: New → Web Service → Runtime: Python → Build Command:
   `pip install -r requirements.txt` → Start Command:
   `reflex run --env prod --single-port --frontend-port $PORT`.)
3. Дождитесь окончания билда (Reflex собирает фронтенд заново при каждом
   старте — несколько минут).

**Бесплатный тариф Render**: сервис засыпает без запросов ~15 минут
(первый заход после паузы — 30-50 сек); файловая система эфемерна, SQLite
сбрасывается при каждом передеплое — для реального использования нужен
`DATABASE_URL` на управляемый Postgres.

## Осознанные упрощения и известные ограничения

- **Интеграция с платформой MAX**: рабочее веб-приложение с мобильным
  интерфейсом, открывается по прямой ссылке (в т.ч. с телефона) — так
  тестируются мини-приложения на этапе разработки. Официальная публикация
  именно как мини-приложения MAX требует регистрации в кабинете
  разработчика MAX и встраивания через их SDK; `max_stub.py` — временная
  заглушка идентификации на этот период (стабильный id на устройство/браузер
  вместо данных из `window.WebApp`).
- **Оплата сборов настоящая (ЮKassa), не «отметка участия».** Дизайн-спека
  проекта прямо описывает сборы без встроенной оплаты (только отметка
  намерения + ручное подтверждение поступления администратором) — осознанно
  решили оставить реальную интеграцию оплаты как более сильную демонстрацию
  для хакатона.
- **Формы создания используют обычные текстовые поля** для даты и суммы
  вместо кастомного календаря/цифровой клавиатуры из спеки — функционально
  эквивалентно, дешевле в разработке и поддержке.
- **Модель сессии — демо-уровня**: роль и ID пользователя хранятся в
  `SessionStorage` браузера (переживает обновление страницы, не переживает
  закрытие вкладки), не подписаны сервером. Достаточно для демо; для
  реального продакшена — заменить на серверные сессии/JWT.
- **`pages/shared.py` разросся** (~4800 строк: экраны «Дом»/«Контакты»/
  «Управление» и все их диалоги в одном файле). Работает и покрыт ручным
  тестированием, но следующий логичный шаг для поддержки — разбить по
  вкладкам/фичам на несколько файлов.
- Платежи — в тестовом режиме ЮKassa. Для приёма реальных денег
  зарегистрируйте свой магазин и задайте `YOOKASSA_SHOP_ID`/
  `YOOKASSA_SECRET_KEY`.
